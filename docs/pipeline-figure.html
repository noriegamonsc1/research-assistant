Agent architecture · 14 stages · 2 bounded loops · token gates

Research Assistant: from a research topic to recommended directions

A domain-agnostic agent for early-stage research planning. It detects the discipline, searches that field's literature, finds open problems, proposes concrete directions, and checks every claim and citation before writing the report.

The LLM reasons, the APIs remember. Every reference comes from a database record retrieved in the run; the model may only cite those records.
LLM step API call or deterministic code Quality gate Loop back Reads the shared, cached paper list

Input

Research topic (1–3 sentences, required), plus optional field and researcher context: career stage, time horizon, resources, methods expertise. Example: Microplastic accumulation in freshwater fish; MS thesis, 1 year, field sampling access.

UnderstandWhat is being asked, by whom, in which field
01 · intakeLLM

Read the request

Splits the input into the topic itself and the researcher's context: career stage, months available, resources, methods.

Why: feasibility is judged against this context later. Anything not stated stays empty instead of being guessed.

Output: topic context
→
02 · decomposeLLM

Break the topic into facets

Splits the topic into 3–6 searchable parts (population, phenomenon, method, context) with synonyms, field vocabulary, MeSH terms, and non-English terms for regional topics.

Why: a single literal query misses most of a literature. Facets also feed the gap matrix.

Output: facets
→
03 · detect_fieldLLM + API

Work out the discipline

The LLM picks an OpenAlex field; the agent checks it against where matching papers are actually indexed. If no field holds 40%, profiles are merged as interdisciplinary.

Why: the field profile sets which databases to search, how many years back, and what counts as evidence and novelty.

Output: fields profile
↓
GatherBuild the Evidence Ledger: the only citable sources
04 · plan_queriesLLM

Write search queries

Writes up to 4 queries per database, in each database's own syntax: core queries, review-paper queries, and gap probes (limitations, future research, understudied).

Why: reviews and gap probes surface the open problems papers state themselves.

Output: queries
→
05 · retrieveAPI

Search and build the ledger

Runs queries in parallel (OpenAlex, Semantic Scholar, PubMed, Crossref), adds the most-cited works of any age, follows citations one hop, merges duplicates by DOI then title, and keeps the best-scoring 60–120 records.

Why: the model may only cite ledger records, so every reference in the report is real.

↻ Back to step 04 if fewer than 15 records (max 2 rounds)
Output: ledger shared paper list
⇢
gate · stop_earlyGate

Stop early if evidence is thin

If fewer than 8 papers remain after every search round, the run skips all later stages and writes a short report: what was found, which queries were tried, and what to try next.

Why: no tokens are spent analysing evidence too thin to support a reliable report.

Output: short report.md
↓
AnalyzeWhat is known, and what is still open
06 · landscapeLLM · cached

Map the state of the art

Groups the ledger into 3–6 themes with cited claims, dominant methods and frameworks, and landmark works. Active authors and institutions are counted from metadata.

Why: grounds the state of the art in retrieved papers, not the model's memory.

Output: landscape groups
→
07 · gapsLLM · cached

Find open problems

Combines three signals: gaps papers state themselves, facet pairs with few papers (structural gaps), and conflicting findings. Each gap gets a cause and citations.

Why: directions must build on evidenced gaps, not on "more research is needed".

Output: gaps
→
↓
ProposeGenerate, check for prior work, red-team
08 · directionsLLM · cached

Propose research directions

Drafts 6–8 directions, each with a research question, cited novelty argument, closest prior work, method sketch, resources, month estimate and risk.

Why: uses the field's own idea of novelty and the researcher's context, so ideas are new and doable.

Output: raw_directions
→
09 · novelty_checkGate

Check it isn't already done

Searches each research question directly, then one batched call labels every direction done, partly done, or open. Done directions are dropped; partly done ones must state how they differ.

Why: the most common failure of idea generators is proposing published work.

Output: candidates
→
10 · critiqueGate

Red-team the directions

A separate reviewer with a fresh context scores novelty, feasibility, significance and specificity (1–5): accept, revise or reject. Hard rules override it, e.g. too long for the horizon forces revise. With 3 or fewer candidates it runs at medium effort.

Why: a model grading its own ideas tends to approve them.

↻ Back to step 08 once, only if fewer than 3 directions are usable; only flagged ones are redone
Output: critiques
↓
DeliverChoose, write, verify, assemble
11 · rankCode + LLM · cached

Rank and recommend

Weights scores by career stage (MS favours feasibility, PhD novelty), penalises risk, and picks the top 1–2 with cited reasons and what would change the choice.

Why: makes trade-offs explicit and tunable.

Output: ranked
→
12 · writeLLM · cached

Write significance

Scholarly, practical and societal significance as cited claims, each with a concrete anchor: a number, population, place, policy or cost.

Why: blocks generic "increasingly important" claims.

Output: draft
→
13 · verifyGate

Verify citations and claims

Removes keys not in the ledger, checks claims against the abstracts they cite in batches of 40, confirms DOIs resolve to the same title, and flags generic phrasing.

Why: last defence against invented or misattributed citations.

Output: qc
→
14 · renderCode

Assemble the report

Drops unsupported claims, labels partly supported ones, numbers references, and builds the bibliography from database records only.

Why: the model never writes the reference list.

Output: report.md
ThroughoutApplies to every model call

Cost cap (optional)

Set a per-run limit with max_cost_usd in config/rubric.yaml or RESEARCH_ASSISTANT_MAX_COST_USD. Once the estimated spend reaches it, every later call runs one effort level lower and the revision round is skipped. Verification always runs. Token use and cost per stage are recorded in qc_report.json.

Output

A report with five sections: 1. Significance · 2. State of the art · 3. Gaps and open problems · 4. Candidate directions (research question, novelty, feasibility, risk) · 5. Recommendation. Alongside it, qc_report.json records claim support, removed citations, DOI match rate and literature coverage, and flags the report as low confidence when checks fail.

Built as a LangGraph pipeline with role-specialized LLM nodes (Researcher, Critic, Writer). Field-specific behavior lives in a YAML config, so new disciplines are added without code changes.
